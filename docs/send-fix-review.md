# DLL 文字、图片发送修复与离线验收

## 当前结论

本分支针对上游公开的文字和图片发送路径生成独立候选 DLL。
默认没有发送许可，不能发送；没有部署或加载到微信，也没有完成真实账号兼容性验证。
离线检查通过不等于微信一定能发出，也不等于账号没有风险。

源码基于上游 main `a9d3f27e4afbe4af85ba72a0a9d93ef8f16e594f`。
旧只读修复分支保留，本分支没有合并旧分支，也不涉及小麦项目。

## 修复内容

| 问题 | 处理 | 验证边界 |
| --- | --- | --- |
| 空参数、类型错误仍可进入发送 | 严格校验字段、UTF-8、NUL、长度及内部接收人 ID | 错误请求下调用计数为零 |
| 路径 UTF-8 字节数覆盖 UTF-16 长度 | 单独构造 UTF-16 路径，保留正确长度、容量和终止符 | 中文、emoji 和字符串边界检查 |
| 声明容量大于实际分配 | 分配完整 capacity+1；宽字符串短模式容量为 7 | ASan/UBSan 与 MSVC 检查 |
| 发送结构部分分配失败仍往下执行 | 所有缓冲区在私有调用前准备完毕，分配失败回收 | 逐分配点故障注入 |
| 私有调用后无条件 success | HTTP 202 / unconfirmed，IsSent=null，DeliveryConfirmed=false | 不能由内部返回值推断送达 |
| 多请求并发、超时后重复调用 | 串行进入私有调用；一次性许可、重复请求回读结果 | 并发及异常重放检查 |
| 进程重启可能重复使用许可 | 进入私有函数前 CREATE_NEW 消耗标记并 FlushFileBuffers | 重建控制器、许可竞争检查 |
| 上游 HTTP 开放范围太大 | 仅回环地址、Bearer 鉴权、具体请求和内容摘要匹配 | 未配置许可 423，错误凭据 403 |
| Windows 端口复用、启动状态误报 | 独占绑定；绑定失败不启动、不改占其他端口 | 实际端口冲突用例 |
| 版本不匹配仍计算私有地址 | 精确 4.1.10.27、文件 SHA256、x64 PE、地址权限及上下文检查 | 不自动适配其他版本或猜偏移 |

发送候选只编译版本代理和本分支的新发送实现；原数据库、XML、回调、MinHook、
隐藏模块及防撤回初始化不进入此构建。旧工程仍保留，**不要用旧工程的全功能产物
替代本次独立构建产物**。

Windows 独占绑定的依据：[Microsoft 的 SO_REUSEADDR / SO_EXCLUSIVEADDRUSE 说明](https://learn.microsoft.com/en-us/windows/win32/winsock/using-so-reuseaddr-and-so-exclusiveaddruse)。

## 一次性许可边界

加载时只读取 `%LOCALAPPDATA%\VW12-WeChatHook\send-approval.json`，不自动创建许可。
缺失、损坏、过期或已经消耗的许可全部保持锁定。许可必须同时匹配随机令牌、请求编号、
内部接收人 ID、文字/图片类型、完整内容摘要和微信 DLL 文件摘要，最长有效十分钟。
没有 HTTP 启用或解除锁定接口；不记录令牌、正文或接收人到日志。

只有用户审阅改动、风险及具体首条消息并明确批准后，才可以另行准备真实许可。
许可消耗标记应保留；不能为重试而自动删除。即使进程崩溃或 HTTP 超时，也只能先核验，
不能换请求编号再发一次。状态接口的 IsLogin=null 表示没有可靠登录证据，不是未登录。

调用最多进入一次，不做自动重试或备用通道切换。尚未核定的显示名不能直接作为 wxidorgid，
必须先绑定正确的内部 ID；不会按同名联系人或群名猜收件人。

## 已完成的离线验证

`tests/send_layout_tests.cpp` 直接使用生产参数构造及调用顺序代码，覆盖短字符串边界、
中文/emoji、宽路径长度、容量分配、每个分配点失败、构造器异常、参数异常及保留所有权。
在 PM 用地址/未定义行为检查器，在 PW 用 MSVC 运行。

`tests/send_api_tests.cpp` 使用模拟后端，验证严格输入、审批范围、错误处理、32 路并发、
异常后重放、持久消耗、两个控制器竞争、许可被修改、实际文件句柄和 SHA256、超大请求、
回环 HTTP 及端口占用。另用生产后端确认没有 Weixin.dll 时拒绝执行，且不主动加载微信。

`tests/send_proxy_tests.cpp` 在普通测试进程内加载候选，检查 17 个版本代理导出，以及
128 次并发系统版本查询。这个测试进程没有加载微信模块，也不会启动候选的微信服务入口。

测试只使用合成内容、测试令牌和临时文件。没有读取聊天记录、操作微信界面、调用微信
内部函数或发送真实消息。最终数量、构建用时、采样峰值和产物 SHA256 以构建报告为准。

`650afbfcc22fb5314dde6d40540c6aa59d1b09e00f24149868af8c3e38f86aa4`。

## 必须保留的限制和风险

1. **微信内部 ABI 尚未实测。** 地址来自上游；版本及文件摘要匹配只防止版本漂移，不能
   证明地址、结构和调用顺序正确。上游 create_param2 的注释与代码顺序有出入，本分支
   保留实际代码顺序，未按注释猜改。离线模拟不能替代这个兼容性检查。
2. **异步所有权未知。** 微信可能在返回后使用参数；不能贸然释放。一次性候选保留已进入
   私有调用的本地参数至进程退出，本地参数分配限制 128 KiB。这不是整个微信进程的
   内存限制，也没有证明微信内部如何分配或释放内存，因此不能宣称适合持续批量发送。
3. **内部调用仍可能崩溃或卡住。** SEH 可以记录部分异常，不能修复内存破坏；私有调用没有
   可安全强制终止的超时机制。不能在卡住时杀线程或热卸载 DLL，回退需要正常退出微信。
4. **图片路径限制更严格，兼容性未实测。** 只接受本地固定卷的 PNG/JPEG/BMP，最多
   20 MiB；拒绝任一层重解析点、非规范路径或超过 64 个父目录的路径。使用卷 GUID 路径，
   所有祖先目录和图片都锁住；进入私有调用后这些锁保留到进程退出，可能阻止相关目录的
   写入句柄、重命名或删除，不适合长期使用。微信内部函数是否接受这种路径尚未验证，
   不可为了兼容性失败而退回未经保护的原路径。类型头/大小/摘要不是完整解码或恶意文件审计。
5. **普通文件/PDF 发送未实现。** 上游 release 有接口字符串但公开源码缺失，不能拿不明
   二进制补齐。本候选 /send_file_msg 明确返回 501；GIF、XML 及其他发送形式不开放。
6. **网络服务并非完整安全审计。** 仍使用上游内嵌 httplib；限制四个工作线程、32 KiB 请求
   和读写超时，但底层排队机制没有硬内存上限。只允许回环访问；不能因此暴露到局域网或公网。
7. **账号风险无法由离线检查排除。** DLL 在微信进程中调用非公开接口；不能承诺不触发限制。
   HTTP 返回和本地记录都不能证明收件端实际收到。

## PR #1 审核问题修复（基于 a0bc20f）

**P1：图片摘要没有绑定后续按路径读取的对象。** 原实现只锁住最终文件，父目录 junction
仍能替换；而且 PreparedCall 销毁时就释放了文件句柄，没有覆盖异步读取。现改为从盘符
获取固定卷 GUID，然后从卷根开始逐级打开父目录，拒绝每一层重解析点，并保留不允许
写入/删除共享的数据读取句柄。必须先锁父目录再打开下一层；仅 FILE_READ_ATTRIBUTES
句柄不参加数据共享检查，不能用作这把锁。每个句柄的最终卷路径也必须与目标路径一致。
摘要检验和原生参数使用同一条卷 GUID 路径；不再把用户原盘符路径传给私有函数。

进入私有调用前将整个 LockedImage 标记为保留，文件和父目录句柄直到进程退出才回收。
预检失败、许可消耗失败或尚未调用时，RAII 正常释放，不产生永久锁。没有创建快照副本、
挂载磁盘、修改盘符、junction 或源文件；只有离线测试在自己的临时目录创建合成 junction。
本机制处理的是常规文件系统路径替换，不是对恶意同权限进程、管理员或内核攻击的完整防护。

新增 tests/send_image_tests.cpp：真实创建父目录 junction 并确认校验前拒绝；验证普通父目录
和更高祖先不能写入、重命名或改成 junction，重复打开真正传入的路径仍得到批准摘要；
检查原生参数中的路径、移动所有权、预检失败释放锁，以及对象销毁后异步锁仍保留。
29 项断言均在 PW 上通过，不调用微信。

**P2：CreateThread 到 worker 固定模块之间可被 FreeLibrary 卸载。** 将 GetModuleHandleExW
的 PIN 提前到 DllMain 中筛选出主进程之后、CreateThread 之前；固定失败不创建线程。
固定成功后即使线程创建失败或端口绑定失败，模块也保持到进程退出，不能热卸载。

新增 tests/send_lifetime_tests.cpp：仅复制测试程序为临时 Weixin.exe，隔离 LOCALAPPDATA，
没有 Weixin.dll 和许可；借用审核复现中的 loader-lock 调度方式，在 worker 获得执行机会前
立即 FreeLibrary。2 次主进程检查均保持模块映射，renderer、crashpad 两个子进程筛选路径
均可卸载；随后子进程正常退出。父测试独占预留 PW 回环 30001，使 worker 仅走绑定失败路径，
不启动候选服务；端口已占用则测试报错退出，不修改占用者。每个子进程十秒超时。
这些测试覆盖了旧代理测试没有进入的启动路径，但不证明真实微信的 ABI、送达或账号安全。

## 构建、部署与审批

PW 使用现有 VS2019 v142 编译器运行 `build/build-send-fix.ps1`，单构建任务、五分钟超时，
保留 10 GiB 磁盘空间。进程树按秒采样，超过 2 GiB 停止；不是 Windows Job Object
硬内存限额，可能漏掉瞬时峰值。实验文件只保留一套，失败构建缓存由后续构建覆盖。

产物是 `artifacts/send-fix/version.dll`。本轮只保留于 PW 构建目录和 PM 交付目录；
没有复制到 VW12 微信目录，没有恢复旧 DLL，没有生成真实许可或重新打开微信。
后续真实试验必须先说明收件人、消息、加载方式、剩余风险和回退方法，等用户明确批准。
当前阶段不启用国泰君安期货的实时转发。
