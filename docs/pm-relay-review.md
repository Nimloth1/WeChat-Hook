# PM → VW12 自动转发：无频率配额、流式附件、原生视频与卡片

本变更取消此前自行加入的180秒间隔、滚动24小时120条/64MiB配额，配置v2中彻底删除三个字段。
PM和来宾均不再检查这些配额。每条完成后立即处理下一条；只有没有可发任务时才等待下一轮输入。
仍串行调用、等待真实原生资源释放，未知结果仍停止且不重试。这些是执行互斥和防重复机制，不是发送频率政策。
没有微信官方“安全频率”依据，不承诺取消配额或任何其他速率可以避免账号安全提示。

本变更未部署、未创建发送许可、未发送消息、未操作登录或VW11。现有生产运行版本不因本次开发自动更换。
未修改小麦采集源码、其他发送渠道、原有采集水位或消息正文归档。目标、来源、机构仍来自两端一致的私有配置。
所有公开ID均为合成示例；正式ID和配置不进入仓库。

## 内容与大小

| 类型 | 来源与发送方式 |
| --- | --- |
| 文字 | type=1；保留发送人@gtja/gtja sg前缀，直接调用/SendTextMsg；取消2000 UTF16单元检查及长文转TXT |
| 图片 | type=3；只读已有Mac V2附件，64KiB块解密到私有暂存文件，按像素/大小选已有最清晰版本 |
| 普通文件及音频文件 | type49的已有file元数据，按名称/重名后缀/实际字节数寻找已有下载；调用/send_file_msg |
| 视频 | type43的已有video.md5/size，从msg/video/<月>/<md5>.mp4取稳定副本；调用/send_video_msg，聊天内视频类型43 |
| 链接卡片 | type49的sub=1/4/5/68，使用小麦已有“渲染标题+最后一行URL”；调用/send_link_msg，卡片类型49/5 |

取消自动层单个附件20MiB、DLL图片20MiB及文件/视频100MiB检查。附件流式复制/摘要/上传，JSON和SQLite只存描述符，
没有按附件大小增长的base64字符串。DLL继续使用同一个受锁文件及稳定卷路径，流式校验摘要；不改变路径锁和原生对象生命周期。
文字Arena按实际UTF8缓冲需求预留，短文字仍预留原有128KiB；同时移除MakeNarrow原有32768字节门槛，长文字不再受固定Arena的隐性门槛限制。
扩展预留在持久消耗许可前取得，仍受已有全局16MiB参数预算约束；不因新文字绕过保留/回收统计。

“取消大小限制”指取消上述业务门槛，不等于无限资源：控制JSON与DLL HTTP体为16MiB内存预算，
JSONL单行仍为1MiB，路径/文件名受系统约束；NativeRetentionBudget仍为16MiB/256句柄。
元数据待发区100MiB、SQLite200MiB、媒体索引50000条及至少1GiB磁盘保留量仍在，资源不足会明确停止。
微信客户端/服务端真实容量与兼容性不由本工具决定，大文件真实发送未验证。

## 视频与卡片边界

不转码原视频、不把视频当普通文件冒充成功。只接受已有MP4，检查ftyp；已有FFprobe探测时长，FFmpeg提取首帧JPEG封面。
工具路径可由私有配置ffmpeg/ffprobe指定，默认使用PM既有/opt/homebrew/bin工具；不下载依赖、不访问网页。
视频工具仅允许file/pipe协议，单次分配64MiB保护、单线程、30/60秒超时；每50ms采样子进程RSS，超过512MiB时结束本次工具进程组，控制输出最多4096字节。
采样保护不是瞬时RSS硬上限，解码峰值仍取决于分辨率和编码。本轮除64×64合成视频外，既有归档中一条真实来源的8664386字节、59秒MP4也已离线生成32162字节JPEG封面；不代表微信实际发送验证。
两份素材分别绑定摘要、时长，所有原生引用归零后才删除。MP4/JPEG格式与时长1–86400的接口契约不变。

卡片仅从已知sub类型提取最后一行URL；不把普通文字中的URL升级成卡片。已有JSONL不保留独立摘要和封面，
因此description为空，不声称还原原始摘要/封面。标题256、摘要2000、URL2048 UTF16单元及HTTP(S)字段契约沿用PR8；
不可执行协议、用户信息、非法端口、空白等在发送前拒绝，不自行截断URL或改成其他消息类型。
原生视频/卡片尚无本项目真实发送验证，不把隔离测试称为真实微信已送达。

## 流式协议与持久语义

SSH固定VW12别名、EncodedCommand、COMPUTERNAME检查；不新增监听端口或来宾常驻服务。
每个请求第一行是ASCII JSON控制帧，必须以换行结束，最大16MiB；普通控制请求禁止附加字节。
`operation=health/dispatch`保留原意；新增`upload`只暂存文件，不创建许可、不调用微信。
上传控制字段恰好operation/policy_sha256/job/role，后续二进制流必须与描述符size及SHA256一致且精确EOF。
角色只能是media或thumbnail，落点固定为state_dir/spool/<64位任务ID>/<role>.bin，路径不接受调用方任意指定。
已有文件或尝试记录拒绝覆盖；失败仅删除本次新建的未完成文件，绝不删除别的调用留下的文件。
附件描述符为filename/size/sha256；视频payload为media/thumbnail/duration_seconds；卡片为title/description/url。

PM先持久claim，再依次上传本条所需素材，核对回执后唯一一次dispatch。上传用临时wire文件拼接头部和64KiB块，
SSH从文件读取，避免管道互等以及进程内完整附件复制。每次上传独立进程，上限900秒；dispatch仍90秒。
上传失败也不自动重传/重发；可能遗留本条暂存文件，链路停止供人工判断，不扫描清理其他任务文件。
来宾查验全部素材摘要/长度后移入角色独立目录，再创建逐条120秒许可和持久尝试标记。
只有202、NativeEntered=true、Replayed=false、消耗标记存在才记submitted_unconfirmed，仍不等于送达。
结束撤销本条许可，等待资源归零后清理素材。PM持久完成回执后再清理本地素材，清理失败不篡改已完成回执。
现有DLL防重放标记、双端SQLite、未知结果暂停和不自动重试全部保留；没有任何重置/补发入口。

## 24小时规则：本次仅说明，未更改

1. 尚未入队的源事件：早于初次启用时间，或超过24小时/在未来，跳过；不触发补历史。
2. 已入队的ready任务：发出前发现超过24小时，抛pending_job_expired，在主循环内持久暂停整条链路。
3. 等待下载的附件：超过24小时，抛attachment_expired_requires_review，同样暂停整条链路。

这不是微信限制，也不是每天重置；是原实现的陈旧任务判断。暂停后后续新消息也不会发送，KeepAlive不能清掉暂停。
本次没有擅自选择“丢弃旧任务”或“继续补发旧任务”；这两种行为会改变内容范围，需用户明确选择。

## 审核后迁移部署

这次需要升级DLL和两端Python，不能只编辑正在运行的配置。候选固定DLL摘要见tools/relay_common.py和配套结果，
与旧生产DLL不同；旧DLL会被新执行器的摘要校验拒绝。正式替换仍需用户正常退出一次，不热卸载/强制结束微信。

先停止PM旧LaunchAgent、保留两端旧配置小副本并确认无在途请求/许可，再部署审核DLL和全部relay_*.py。
以现有配置为基础，只将policy.version设为2并删除interval_seconds/daily_messages/daily_media_bytes。
来源、目标、机构、enabled及state_dir必须保持不变。升级脚本读取私有配置，不输出密钥或正文：

```sh
python -B tools/relay_upgrade.py --config <新配置> --previous-config <升级前配置>
```

PM通过collector.lock排除旧运行器，Windows通过executor.lock排除来宾执行器；两端分别执行。
迁移仅允许v1→v2同范围变更，拒绝paused、ready/dispatching/review_required、剩余payload或waiting附件。
有未完成任务时先处理旧任务；不能删除账本绕过阻塞。保留cursor、activated_at、所有历史请求/回执及磁盘标记，
仅更新已有policy_scope并记relay_protocol=2；重复迁移无变化不写盘。**不得重新baseline。**
对齐两端配置、更新私有服务入口/监控引用后恢复旧LaunchAgent；整个迁移没有自动发送动作。
审核和部署后仍需测一次真实转发周期、核对Healthchecks探针。本文离线测量不能替代它。
