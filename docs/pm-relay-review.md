# PM 小麦存量采集 → VW12 独立自动发送层

## 行为与范围

PM 的小麦生产仓库维持原状，三个既有渠道、采集水位和微信读取程序均不改变。
本工具只读跟随小麦已经写出的 `messages.jsonl`；JSONL 轮转、截断或已消费边界被改写时暂停，
不猜测新的偏移。首次显式建立基线跳过历史，偏移与入队使用同一 SQLite 事务，接收失败不越过该事件。

来源只接受私有配置中的原生群 ID、明确机构白名单、非自己发送的群消息。
文字保留 `发送人@gtja：正文`（新加坡机构用 gtja sg）；超过2000 UTF16单元时完整保存为文本附件。
图片复用小麦已有的本地 DAT 缓存密钥推导/V2 解码步骤并改为有界读取，不点客户端、不补下载、不读取进程或数据库密钥；
文件只有在本地名称及字节数核对后才交接，单件上限20MiB。缺附件时留待后续检查，不发占位文字；
文字可以先于尚未就绪的附件发出。因此不保证原会话中的跨类型严格顺序。
附件每轮最多检查10条，按本地 rowid 从上次检查位置继续，到末尾后绕回，缺失项不占住队首。
游标仅在 PM 进程内保存，重启会从头开始，但之后继续轮转；空轮询不为游标写盘。

视频、链接卡片、语音、表情、系统消息不接入自动发送；原生视频不会偷偷按文件降级。
音频若来源本来就是普通文件消息，会沿用文件发送。不能解码、超限或等待超过24小时的附件
需要人工处理；不自动丢弃再假报成功。文件保留小麦的名称/重名后缀/大小查找规则并采用有界读取，不宣称验证了原文件的远端来源摘要。

两个终端使用相同、默认关闭的 policy，并互核摘要。目标原生群 ID、来源 ID、机构、间隔和滚动24小时
配额都绑定 policy。示例是间隔180秒、最多120条、媒体总量64MiB/滚动24小时；这不是防封阈值或账号安全保证。
两侧账本保留 claim 的 attempt 时刻，并在终态事务内记录本机 completed 时刻。间隔及滚动配额从
completed 保守计时：来宾在撤销许可、检查回收并落账后完成，PM 在收到并核验该回执后完成。
PM 因而等到上次远端完成回执后至少180秒才认领下一条，不把 SSH 准备耗时变化升级为来宾拒绝。
配额未到期时任务保持 ready，不调用远端、不创建许可、不记录尝试；这不属于重试已发送任务。
completed 是本地执行完成时间，不是送达时间；两侧不比较绝对时钟。此约束针对正常耗时变化，
不保证在系统时钟跳变或绕过本客户端直接调用接口的情况下仍然同步；来宾限流和未知结果暂停仍保留。
任何修改运行中配置的行为都暂停；扩大范围不能热更新后直接发送。`pause` 命令无需重启微信，
但不能撤回已经进入原生函数的一次调用。

## 执行与证据

### VW12 对 PM 的接口

`relay_guest.py` 是独立于小麦的发送端接口，不要求 PM 修改 DLL、拼许可文件或取得数据库密钥。
当前传输是经已验证的 SSH 公钥通道发送 JSON RPC，读取单个 JSON 回执；不额外开放 HTTP 端口。
`relay_pm.Transport.request()` 是可复用的 PM 客户端入口，既可以由本 PR 的独立 JSONL 跟随程序调用，
也可以在小麦后续增加 `vw12` 渠道时复用。**小麦生产的 `FORWARD_CHANNEL` 目前尚未增加 vw12，
不能把现有 JSONL 跟随程序说成已接入了生产渠道列表。** 两种 PM 输入方式不应同时开启。

| operation | 请求字段 | 回执 |
|---|---|---|
| health | operation、policy_sha256 | 执行器启用状态、账本计数、许可存在性、DLL只读状态 |
| dispatch | operation、policy_sha256、job | 请求ID、内容摘要、持久状态、POST尝试数；不代表送达 |

`job` 的字段为 `id/recipient/source/message_id/source_ts/corporation/kind/payload`。
文字 payload 为 `{"text":"正文"}`；图片/文件为 `{"filename":"名称","sha256":"摘要","data_b64":"内容"}`。
目标、来源和机构必须匹配来宾的固定 policy，调用者不能临时传一个新收件人改变发送范围。
请求ID由来源消息ID、种类和目标稳定生成。PM 客户端必须像本实现一样先持久 claim，再调用 dispatch；
并在核验回执后持久记录本机完成时刻，以此约束后续任务的间隔和滚动配额。
遇到丢失回执时暂停，不能套通用自动重试。旧ID再次调用只读回执，实际POST为0。

因此，产品上的接入形态可以是“小麦新增一个 vw12 渠道 → 调用 VW12 接口 → DLL”。
本 PR 已交付接口/执行器以及独立输入入口；把它挂入小麦现有渠道工厂，是另外一处小麦代码接入，
尚未实施或部署。若需要 HTTP 形状，可另加受认证的外层，不需把 DLL 本身改成无许可网络入口。

PM 使用稳定的来源消息编号/类型/目标生成请求 ID，再经固定 VW12 SSH 别名和 EncodedCommand
调用一次性执行器。正文走 stdin，不进入 shell；VW12 执行器只接受 COMPUTERNAME=VW12。
固定已审核 PR8 DLL 及腾讯模块 SHA256；单次执行器由 Windows 内核文件锁串行化，异常退出会释放锁。
不会新增来宾服务、监听端口、计划任务、自动登录或微信重启程序，也不访问 VW11。
入口在导入 relay_common 前显式加入入口文件自身的目录。嵌入式 Python 的 `._pth` 不会自动加入
脚本目录，仅切换 cwd 或设置 PYTHONPATH 不能保证可用；本实现不修改共享解释器的 `._pth`。
该目录需要与其他部署代码一样保持受信、不可由非管理用户写入；此变更没有增加依赖下载或查找其他目录。

每个任务均在 PM、VW12 两侧先持久标记 dispatching，再创建仅绑定本条内容、收件人、类型和模块摘要的
120秒许可。POST 前写持久客户端尝试标记，保留 DLL 防重放标记；结束只撤销自己的许可，不覆盖其他操作者许可。
文字/图片/文件的原生摘要格式沿用 C++；中转账本/传输使用独立的 ASCII JSON 编码，避免中文元数据把整个
大型 base64 JSON 扩成双字节字符串。

只把 HTTP202、NativeEntered=true、Replayed=false、有原生消耗标记的响应记为
`submitted_unconfirmed`，**没有把它记为成功送达**。允许后续独立消息继续，是自动模式需要批准的行为选择，
并不是新实现了微信送达回执。许可撤销后观察实际资源计数，最长40秒等待自然归零；
只在无故障、无引用/句柄时删除本条物化文件，不靠超时强行释放。其他路径保留文件并暂停。

SSH/HTTP 超时、拒绝、响应不符、缺消耗标记、回收故障或崩溃遗留 dispatching，都暂停，不自动重试。
PM 丢失回执也不通过重新发 POST 对账；须人工查账。KeepAlive 重启后仍保留暂停和不确定状态。
新任务不会绕过未决状态；旧 ID 查询只返回账本，不再次 POST。请求 id、来源编号、时间、类型、摘要和结果证据长期保留，
完成后删除待发 payload 的活动记录。SQLite 页和日志不等于安全擦除，目录仍可能包含明文残留，必须保持私有。

当前 DLL 不能可靠识别登录/安全退出，自动层也不能自动判断账号安全提示；`IsLogin=null` 不会触发扫码或
重新登录。发生安全提示必须人工暂停，检查后再决定恢复。这是仍然存在的运行风险，不能用资源归零证明账号安全。

## 资源、持久运行和上线要求

任务状态与大 payload 分表，更新状态不重写整份附件。重复收件、空轮询、只读状态无变化不写盘；
完成后 SQLite 空页供后续消息复用，不逐轮 VACUUM。待发 payload 100MiB，数据库文件200MiB，
附件定位索引50000条；超限暂停、不删除防重放证据。旧账本不迁移，使用全新隔离状态目录。
本轮离线修复新增 jobs.completed 字段；不能复用审核旧版的临时账本，更不能删除真实防重放账本来适配新结构。
媒体输入/输出均在整文件读取前后限制20MiB；JSONL单行最多1MiB，SSH请求最多29MiB，
至少保留1GiB空闲空间。大附件的来宾入队及物化另留六倍内容大小的操作空间。

PM 需以持久主机 LaunchAgent 运行 `relay_pm.py run`，不在沙箱/agent进程驻留。
部署前登记独立服务到既有 KeepAlive 探针，探针检查 launchd 与 `status` 的 paused 状态；
沿用既有 Healthchecks 全通知渠道。暂停时程序额外向用户本人 Bark 一次，不向群发送故障通知。
日志仅包含状态/异常类型，生产部署时需限额/轮转；不得保存 token、原始请求或完整异常文本。
这些调度和监控**尚未安装**，不能把当前离线代码称为已经上线。

正式启用时先对齐 PM/VW12 policy、核对新 DLL/无许可/旧标记完整，用 `baseline` 在当时EOF建立基线，
最后由调度器启动。不得手动运行一次生产 `run` 来冒充调度器验证。
需测量实际完整转发周期写盘，并确认日志轮转、Healthchecks/KeepAlive 探针已经覆盖新服务。
与真人群相关的配置及原生 ID 不写入公开仓库。PR9 审核版文件已安装到两端，但健康 RPC 在嵌入式
Python 导入共享模块时失败；本入口修复候选尚未部署。当前两端 policy 关闭，无生产水位、调度或发送。

## 配置与命令形状

`tools/relay-policy.example.json` 中的 group ID 是合成示例。PM私有配置为：

```json
{"policy": {"与示例相同结构": "替换为已批准的真实值"},
 "state_dir": "/私有/独立状态目录", "archive": "/小麦/data/ingest/messages.jsonl",
 "xiaomai_root": "/小麦项目目录", "account_dir": "/已登录源账号的附件目录",
 "guest_python": "C:\\已安装的Python\\python.exe",
 "guest_script": "C:\\独立代码目录\\relay_guest.py",
 "guest_config": "C:\\私有配置目录\\relay.json"}
```

来宾配置仅含相同 `policy` 和独立 `state_dir`，不需要采集数据库密钥。

```sh
python3 -B tools/relay_pm.py status --config /私有/pm-relay.json
python3 -B tools/relay_pm.py baseline --config /私有/pm-relay.json
python3 -B tools/relay_pm.py pause --config /私有/pm-relay.json
```

`baseline` 不能覆盖已存在的水位；没有自动 resume/reset 命令。暂停恢复前必须先处理未决任务、核验资源及许可，
不能通过删除账本或标记绕过防重放。

## 离线验证

```sh
python3 -B tests/test_pm_relay.py
python3 -B tests/measure_pm_relay.py
```

macOS在既有小麦venv执行24项测试并跳过Windows锁测试；PW隔离目录25项全部通过。测试包含多组参数/故障子场景：
基线、半行、轮转/改写/截断、入队失败事务回滚、重复无写盘、机构/目标过滤、超长文字、附件等待、
跨重启频率配额、拒绝/超时/伪重放/资源未释放、许可撤销、持久防重放及异常退出锁释放。
新增覆盖两端10秒→1秒准备耗时变化及更长回执耗时、完成计时跨重启、滚动条数/字节额度边界，
以及25个等待附件中第11/25条就绪、新增文件、重启后继续轮转、单轮最多10次检查和等待轮询零写盘。
启动回归用 `-I` 从不相关 cwd、含空格/中文的入口路径运行 `--help`，cwd 中放置同名报错模块，
并设置 PYTHONPATH 指向该目录。`RELAY_EMBEDDED_PYTHON` 可指定额外的嵌入式解释器重复此回归。
PW 使用 VW12 既有 Python 3.13.17 的二进制副本（31个文件逐一核对摘要），隔离 `._pth` 仅包含
标准库 zip 和运行时目录：旧入口在导入阶段失败，修复入口通过。临时副本均已清理；没有在 VW12 执行补丁。
`--help` 验证到参数解析可启动，不等同于真实健康 RPC 已恢复；后者仍需审核并部署后验证。
Hook完全由替身实现，不加载真实微信，也不模拟伪造服务端送达。DLL代码未修改，PR8既有验证不重复冒充为本层端到端测试。

20MiB合成附件完整周期的峰值/写入保留自 b4f0344，入口补丁未重跑这项测量；最新源码摘要另列于配套结果。
这些是离线进程计数，
不能替代上线后一次真实周期测量，也不能据此保证账号安全。
