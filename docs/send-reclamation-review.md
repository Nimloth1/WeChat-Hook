# PR #6：异步参数回收实现审查说明

本次已把回收接入生产 `NativePrepared`，不再将正常请求的所有参数、图片文件和父目录句柄永久保留。本文描述离线候选，不是部署记录；未验证真实微信完整业务工作体、真实连续图片发送、送达或账号安全。旧的累计保护候选和模拟器研究记录不是本实现的验证替代物。

## 旧问题与正常行为

上游 `src/wx_send.cpp` 只分配并发送，未配对回收；手工控制块使用 `0x200000005`/`0x200000006`，没有对多余持有者的匹配释放。原后端还无条件保留每次 Arena 和图片锁，新许可使这部分逐次累积。它每次正常调用都会发生，是静默增长。

现在使用固定原生分配/释放入口，初始控制块只拥有一份强引用及隐含弱引用。发送入口复制参数后，调用方通过真实组合状态析构撤销自己的一份所有权；队列及任务副本保留各自的引用。正常销毁由原生具体析构和配对分配器完成，不直接 `free` 整个 Arena，也不靠等待几分钟或重启。

`Prepare` 只校验模块、图片和许可前提，预留请求资源；原生分配、构造、发送、源状态析构都位于 Controller 持久消耗许可之后。消耗前撤销、文件变更、额度拒绝仍不执行本次请求的私有函数；回收先前已批准请求的资源不依赖新许可。

## 实现位置与所有权

- `include/send_layout.h` 的原生构造分支：文字控制块按原生工厂的 `0x758` 字节分配；图片保留原有较大尺寸。两者初始计数为 `1/1`。大于等于 4096 字节的 MSVC 字符串缓冲保留匹配的对齐及原始指针，不能混用普通 HeapAlloc 字符串。默认的旧布局分支只保留给历史布局回归；生产明确传 `native=true`。
- `src/send_ownership.inc`：实际生产 `NativePrepared`、原生 Heap、每请求租约、消息完成观察器和收取器。只给本模块新建及跟踪到的图片克隆建立影子虚表；不扫描微信堆，不替换全局原生代码、全局虚表或其他已有对象。RTTI 与未替换槽保持原值。
- 源状态是真实的 24 字节 vector 与 232 字节参数的组合，`0x1678000` 仅对这一完整对象调用，不能对任意 vector 指针调用。成功后源 vector/消息引用/参数成员由它释放；源状态存储、arg1、scratch、已被移动的三个输入节点再由配对分配器释放。
- 每个请求从模块校验起持有同一份原生模块引用，覆盖最后一次延迟析构/释放；故障隔离时也保留模块引用，避免收取器访问已卸载的原生代码。每个观察记录在消息发布前持有一份弱引用，保护控制块及影子表的存活。具体析构返回后才发布完成标志。收取时先还原原生控制块虚表，再撤销本模块弱引用、删除观察记录；其他合法弱引用可继续生存，不指向已释放的影子表。

500 ms 定时器只收取已完成的记录，不用时间判断异步读取已结束；空闲时也可收取。收取器串行化，避免一次主动收取返回时另一轮收取还未完成。运行时及定时器是每进程一份固定开销，模块已由现有 DllMain 固定；不新增 Windows 服务、计划任务、日志轮询或周期性写盘。

## 图片路径锁

原对象销毁不能代表图片路径消费者结束。图片克隆虚函数包装会调用原生克隆函数，为结果建立独立观察记录；原图、子代及后代共享一个文件/父目录锁租约。只在所有已跟踪消息完成具体析构且调用方结束持有后关闭锁。克隆元数据分配失败或结果类型不符时，保留该请求的锁并报故障，不返回一个伪造的成功对象或按时间释放。

图片仍使用原 PR #1 的卷 GUID 稳定路径及逐层非重解析点检查；没有改回可替换的盘符/junction 路径。离线用例实际在原对象销毁后从后代路径重新打开文件并核对摘要，验证锁仍有效；最后释放后写入句柄才重新可用。

**边界：这验证的是跟踪到的消息及克隆的所有权，不是微信全部内部异步 I/O 的穷尽证明。** 当前普通图片处理静态路径包含通过虚函数克隆、以及持有消息强引用的工作对象；还存在其他复合消息代码直接调用图片复制工厂的静态引用。本轮未执行整个真实消息工作体，也未证明所有路径复制都保留消息引用、所有复制均经过被包装的虚函数，或所有图片读取均在这些对象销毁前结束。审查必须保留这个私有 ABI/完整异步链风险，不能据此宣称真实图片发送已经安全验证；若真实链存在绕过这份生命周期的消费者，还需补充适配，不能直接提前关闭文件锁。

## 异常与资源额度

尚未进入私有构造器、所有分配都只属于调用方时，分配失败可配对释放。分配/构造开始前许可可能已经消耗，失败也不以新请求自动重试。构造中途失败、提交/源析构异常、异步析构异常、克隆异常或元数据失败，不能推断对象仍完整或副作用为零；请求资源转入保守隔离，不重试、不清除持久消耗标记，后续新请求返回 `native_ownership_fault_requires_investigation`。原生故障仍可能影响微信进程；SEH 不保证进程完整或账号安全。

16 MiB/256 句柄额度现在约束准备中、待处理及隔离请求。每请求预留 128 KiB 的调用方参数预算，正常完成会归还，可以继续复用；它不是发送总次数上限。没有增大原额度、重置接口或自动重启。`RetainedParameterBytes` 为兼容保留的字段名，在本实现表示尚未归还的保守预留量，不是堆的精确物理占用，也不覆盖原生内部克隆/业务分配或微信整进程 RSS。若原生消费者长期持有对象，额度也可能持续占用；离线循环不能证明真实微信不会缓存这些对象。

状态新增 `NativeResourceReclamationImplemented=true`、`NativeOwnershipMode=native_reference_ownership`、`PendingMessageOwners`、`NativeOwnershipFault`。`NativeResourceReclamationVerified` 与 `RuntimeCompatibilityVerified` 继续为 false，避免把实现存在等同于真实环境验证；所有结果仍为 unconfirmed，不升级成送达证明。各状态快照分别采集，不是送达事务。

## 固定版本与风险

只接受原生模块 4.1.10.27、183094832 字节对应 SHA256 `f487e4f56930456a25fb0d7b058c77e2dcd364e268d49bdfff4dc0e3be26ba36`，并继续检查内存边界及可执行地址。新增配对入口为 `0x680D0FC`、`0x680D138` 和 `0x1678000`；没有变更原发送入口、收件人或消息内容校验。模块不同会拒绝，不自动寻找新地址。

新增自有控制块/图片虚表包装属于真实行为变化，需要重点审查并在批准后再验证真实兼容性。固定摘要、离线检查和没有全局 patch 都不能保证不会出现微信异常或账号安全提示。本轮未部署、不重开微信、不操作登录、不读取真实聊天或 VW11，不创建真实许可或发送请求。

## 可复跑离线验证

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File build\build-send-fix.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File build\test-native-ownership.ps1 -NativeSample D:\offline\Weixin.dll
```

`tests/send_ownership_tests.cpp` 直接包含生产 `send_native.cpp`，运行实际生产 `NativePrepared`、BuildFrame 原生分支、观察器、回收器和 LockedImage。`native_ownership_fixture.h` 要求用户提供固定摘要的磁盘样本；不 LoadLibrary 微信模块、不运行其 DllMain、不访问真实微信进程。仅在合成进程内映射所需指令页，保留真实构造、参数复制、引用计数、克隆及析构指令，替换分配器/free、memcpy、UUID、会话提供器和最外层队列；排队后的业务工作体入口明确替换为失败。

模块保活用例仅加载/卸载系统 msimg32.dll，不调用其业务接口，以验证引用的正常释放及故障隔离。故障夹具注册原始 Windows 展开数据，以允许 SEH 穿过复制的栈帧；原生语言异常处理器替换为 continue-search，不初始化私有 CRT，不验证原生异常清理的正确性。故障用例因此检验的是调用方在未知/未清理状态下的保守隔离，不能称为真实微信异常恢复通过。每种故障在独立测试进程中执行，无生产重置/回收故障对象接口。

验证结果见 [结果清单](send-reclamation-results.json)。本轮完整私有样本仅为离线复现临时保留，报告保存后清理；不把私有 DLL 或提取指令字节提交 Git。测试程序、候选和小型日志保留到本 PR 的审查/部署决定完成。

## 本轮实际结果

Windows 生产路径夹具通过 20,064 项正常检查和 68 项故障检查，共 20,132 项；正常循环 10,000 轮，累计 175,894 次原生参数分配全部配对释放，每轮回到零原生参数分配，句柄净增长 0。160 个并发图片克隆、原对象先析构、两代克隆、晚到弱引用、析构阻塞时不回收、空闲定时收取、模块引用保活/隔离、大 UTF-8/UTF-16 缓冲及逐分配点失败均通过。原生参数峰值 359,680 字节包含并发克隆，不是整进程 RSS。正常夹具 2.7 秒，采样工作集峰值 7,262,208 字节；夹具编译采样进程树峰值 213,032,960 字节。

完整 Windows 构建与回归：布局 257、上下文 84、API 117、图片锁 29、预算 18、实际准备/许可前提 2033；17 导出、128 并发代理查询及生命周期/启动/listen/worker 旧回归均通过。构建 74.7 秒，采样进程树峰值 197,963,776 字节。macOS 布局 257 与预算 18 项在 ASan/UBSan 下通过；没有执行 Windows ASan/UBSan。

最终离线候选 420,352 字节，SHA256 `3b0a1a016d7a186f21c63be98eaacb1a17aa45bc610e843eb5b71f0f09492207`。候选仅在 PW 隔离目录与本地任务输出，未部署。以上结果不等于 10,000 条真实微信发送，也不能替代本文列出的完整异步链/真实缓存生命周期/账号风险审查。
