# 发送第六参数值读取修复

## 故障与范围

用户批准一次向文件传输助手发送 hello。唯一一次 POST 返回422/send_context_unavailable，
NativeEntered=false，未进入微信发送函数；许可撤销，客户端尝试标记保留，没有重试。
这是首次真实预检触发，显性失败、尚无频率数据。用户明确选择继续查修，并确认共用入口最小范围。

当前故障模式涉及 WindowsBackend::Prepare（文字/图片共用）、Addresses.context 与 ExecuteFrame 的第六参数转交。
上游 src/wx_send.cpp 的 BuildSendParam2_Text/Image 仅作为参考，不进入本候选构建，也不修改。
本次只修共用读取契约并补离线回归，不新增偏移、接口、重试、登录操作或新发送许可。

## 证据与结论边界

上游 main a9d3f27e4afbe4af85ba72a0a9d93ef8f16e594f 的两条路径均读取 base+0xA0CE0B0 的64位值，
原样传入 base+0xDF40 的第六参数；没有对读出的值做指针可读性检查。
本分支先前额外要求该值非零、且必须指向至少8字节可读区域，这是未经证实的指针假设。

本轮只从 VW12 磁盘文件读取 PE 元数据、函数区4096字节及数据槽8字节，未打开微信进程或读取其堆。
固定文件 C:\Program Files\Tencent\Weixin\4.1.10.27\Weixin.dll，183094832字节，SHA256：
`f487e4f56930456a25fb0d7b058c77e2dcd364e268d49bdfff4dc0e3be26ba36`。
数据槽的磁盘初始值为1，不是现场运行值；不得以此声称已经读到失败时的值。

静态函数主路径RVA0xDF40–0xE160：7次push使rbp=入口rsp-0x38；
0xE045 的 mov rbx,[rbp+0x68]读取入口rsp+0x30，即第六参数；
0xE0A0 的 mov [rsi+0xD0],rbx原样存入输出结构。该主路径不把rbx当地址解引用。
函数545字节SHA256：`bb1971d1929e46492f51a068420834391446fea9fd81ecf8e107596b12469c61`。
栈参数定位依据 [Microsoft x64调用约定](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention?view=msvc-170)。
不在仓库中放入腾讯二进制或完整反汇编，原始小范围证据保留在任务输出目录。

另对磁盘.text做有界流式候选引用查找（最多前8个候选，每处192字节，不是全量交叉引用证明）。
离线反汇编的0xD635/0xD63F及0x12D025/0x12D02F两处窗口均显示：
从同一0xA0CE0B0槽读取到rax，inc rax，再写回该槽，并复制到结构中的值字段。
REX前缀与无前缀位置产生重叠候选，不能把8个候选当成8个独立使用点。
递增行为与参数构造器的原样复制相互印证，支持将其作为不透明64位值；
不据此猜测准确业务字段名、并发更新语义或整条发送链兼容性。


PW独立Win32负对照直接使用原MemoryRange及原读后判定：合成1/0/max均成功读取8字节，却被旧检查拒绝；
可读指针对照通过。未加载Weixin.dll，未调用任何私有函数。
这些证据确认旧指针限制与此参数构造器的值传递契约不符，能够造成当前错误；
仍未区分本次真实请求究竟是读取失败、零值还是指针可读性项触发，不把静态初值冒充运行现场根因。

## 最小改动

ReadSendContextValue只接受一次完整8字节读取，失败或短读仍抛send_context_unavailable；
读出值按uint64_t原样传递，零和不可用作地址的位模式都不被额外解引用或归类为指针。
WindowsBackend::Prepare使用该读取函数；Addresses.context字段名和布局保留，仅补充值语义注释。

源槽位仍先经过 Module 中的精确版本、批准摘要、x64模块、地址/区域可读性检查；
再用ReadProcessMemory验证实际复制结果和长度。没有去掉模块/源地址检查或在读取失败后继续。
保留原构造器/发送函数地址、参数顺序、一次性许可、持久消耗、串行、无重试和不承诺送达的行为。

## 验证与风险

新增tests/send_context_tests.cpp：0、1、2、高位和全1位模式，文字/图片两条参数转交，
失败返回、0–7字节短读和异常长读拒绝；Windows另使用测试自身地址执行真实ReadProcessMemory，并拒绝空源地址。
合成Invoker仅捕获参数，绝不调用微信内部函数。测试在完整Windows构建中运行，PM另跑ASan/UBSan。

本候选未部署、未重开微信，未再次发送。原始上游ABI的其他参数、异步生命周期、真实送达和账号风险仍未验证。
此修复消除一个已证实的错误限制，不能据此保证下次真实发送成功；不得绕过其他预检或自动重试hello。
