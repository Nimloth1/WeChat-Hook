# 发送 DLL 启动诊断候选

## 实际故障与范围

用户正常重开微信后，VW12 主进程1596加载了审核 DLL（SHA256 650AFB…86AA4），但30001没有监听。
首条文件传输助手测试在 POST 前停止，发送请求、私有调用、消耗记录均为0；许可已删除。
用户确认微信桌面正常，并批准只查修启动问题，要求 DLL 变更先审核再部署。

这是首次观察到的服务启动失败：此前主进程6884监听正常。未取得连续运行的失败率；
客户端显性停止，但原 DLL 的内部失败原因没有保留。故障阻断已批准的实测，用户已明确同意继续。

已完成对照：同一审核 DLL 在 PW 的动态/静态导入、有/无合成许可场景均能启动；
在 VW12 自建空白进程中也能启动，且该进程没有加载真实 Weixin.dll。
VW12真实主进程的加载器入口地址与磁盘一致，初始化标志已设置、模块固定计数已到上限，
未观察到以审核 DLL 为起始地址的存活工作线程；真实进程所用C++/WinSock运行库与系统库摘要一致。
这些结果将范围缩小到真实宿主中的线程创建/服务启动路径，**尚未确定原始错误码或根因**。

本 PR **补齐启动诊断并修复离线确认的错误码丢失，不宣称已修复真实启动失败**。
不改变线程创建、模块固定、端口、回调、发送函数、许可读取时机、失败重试或联系人查询。
同一启动路径中需要区分的位置为：代理初始化、进程筛选、固定模块、创建线程、读取许可/构造controller、
注册路由、绑定socket、进入监听及异常退出；本候选只在原位置记录状态，不新增备用启动路径。

## 变更

新增40字节POD数据导出 `SendFixStartupState`。保留原17个系统 version 代理导出，新导出不是可执行函数。
字段仅含 magic/version/bytes、loader阶段、worker阶段、最后观察到的Win32/WinSock错误、线程ID、
std::system_error数字及category（1=system、2=generic、3=other）。不记录异常what()、路径、账号、正文或token。
所有变化字段用InterlockedExchange写入；没有文件日志、注册表、网络遥测或常驻辅助进程。
诊断字段只用于观察，**绝不参与发送授权、启动决策或重试**；数据可被宿主修改，不能作为安全边界。

`tools/read-send-startup.ps1 -ReviewedSHA256 <审核候选完整摘要>` 用只读进程句柄，
最多读取8KiB的PE/export元数据和40字节状态；从**实际映射的导出表**找状态，而不是只用磁盘RVA。
脚本限VW12/maegl/x64、已安装的唯一微信主进程及固定DLL路径，要求磁盘摘要吻合。
不读线程栈、微信堆、聊天或密钥，不注入、不调用目标函数、不暂停线程。
旧DLL没有该导出时明确失败；磁盘文件换了但进程仍映射旧DLL时，不能误读旧偏移为新状态。

这是逐字段的观察快照，不是整份原子事务快照；需要在稳定终态核对，阶段60只表示进入listen调用附近，
不证明HTTP就绪或微信兼容。bind失败后的两个系统错误是库返回后的最后观察值，
本次已在HTTP库失败清理中保留最后一个socket错误，但它仍可能不是更早的socket选项等操作的首次错误，
不能一律当作整个启动链最初失败的直接原因。

## 验证与未验证

新增合成Weixin.exe测试覆盖动态及静态导入，各自验证正常监听、端口冲突、renderer跳过。
冲突由测试自己独占端口造成，测试要求无HTTP时仍可读到stage100及非零WinSock错误。
正常场景验证监听属于本测试PID、GET返回预期构建且未配置发送许可。
profile在CreateProcess前通过环境传入，避免静态导入时worker早于main而读到宿主profile。
这些进程不加载真实Weixin.dll，不POST、不进入私有函数；测试后清理夹具。

原布局/API/图片路径/代理导出并发/生命周期检查继续执行。新增数据导出不替代既有17个代理函数。
新候选仅在PW编译和测试；未放入VW12安装目录或加载进真实微信，未创建发送许可。
PIN/CreateThread失败、资源耗尽等分支尚未在真实宿主重现，不用人工stage值冒充真实失败证据。

待审核通过后，如用户同意部署诊断候选，应先正常退出微信，再替换文件并核对摘要，再正常打开一次。
随后仅读取诊断数据和OS监听状态，不发送。新候选要取得真实错误码后，才可设计有证据支持的根因修复；
没有自动复活、重载、注入、改端口或重试发送。此前文件传输助手的单次授权不在此阶段执行。


## 已确认的错误码丢失与新增范围

修正前端口冲突场景返回loader=80、worker=100，但Win32/WinSock错误均为0，非零错误码断言失败。
定位到HTTP库在create_socket的失败清理中调用close_socket/freeaddrinfo，返回外层时原错误已丢失。
用户已明确同意将这处同模式问题一起修复。
在 include/httplib.h 的 Windows create_socket 失败路径中，分别围绕 close_socket 和最终 freeaddrinfo
保存/恢复最后一个WSA错误；不改socket选项、地址选择、bind/connect、端口或重试，非Windows分支不变。
此内部辅助函数由服务端和客户端复用，因此修正也会保留Windows客户端创建连接失败的错误值；
成功路径没有变化。原解析失败的提前返回路径不在本次修改范围。
端口冲突断言保留并收紧为WSAEACCES/WSAEADDRINUSE，不用只验证stage或非零伪装原始错误恢复。
真实微信最初启动失败的根因仍未确定；该离线缺陷不能直接等同于真实根因。


## 最终离线结果

完整构建通过：PW MSVC v142，58.9秒，采样峰值218,091,520字节；保护为五分钟、采样2GiB及10GiB磁盘保留。
采样保护不是硬内存配额。原238/69/29项检查、17个代理函数/128次并发查询、4个生命周期场景全部通过。
新增动态/静态导入各3个场景（共6个）全部通过；两个冲突场景均从0恢复为10048（WSAEADDRINUSE），
正常场景HTTP200且无发送许可，renderer阶段40/0且未创建worker。
只读工具在自有PowerShell进程中读取新40字节状态成功（含元数据共766字节），
旧DLL缺少导出被明确拒绝（元数据972字节）；未读真实微信状态或调用目标函数。

候选398,336字节，SHA256：`8ff74d436663f40b80d4514776d5d287976fe01b4add10bbd0b6e3d0dd013442`。
该诊断候选尚未部署或在真实微信中加载；真实启动根因、发送ABI和账号安全仍未验证。
新增导出会改变DLL的导出表和摘要，合成通过不能保证真实微信接受它。
原有DllMain/CRT/TLS初始化风险未在本轮重写；loader阶段0仅表示尚未观察到自定义入口，不证明模块不存在。
本变更不新增生产文件/日志写入；尚未部署，故没有宣称完成真实进程的生产写盘测量。
