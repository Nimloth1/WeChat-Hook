# 普通附件发送（PDF 等）审核说明

## 变更与边界

原 `/send_file_msg` 固定返回501，没有本地文件发送实现。本变更接入既有 Controller、逐条重新读取的许可、持久防重放标记与原生异步所有权管理，不改登录、联系人查询、微信配置、回调或自动转发。不包含部署和真实发送。

接口只接受四个字段：

```json
{"request_id":"unique-approved-request-0001","wxidorgid":"12345678901@chatroom","path":"C:\\approved\\报告.pdf","file_sha256":"64个小写十六进制字符"}
```

`kind=file`，`POST /send_file_msg`，Bearer 认证方式不变。v2许可仍仅限数字 `@chatroom` 群ID；路径、文件摘要、收件人、消息类型与 request_id 必须与人工批准内容一致。文件名来自路径的末段，不能在请求中另填显示名称，因而也被路径摘要绑定。

文件许可的 `payload_sha256` 是以下对象经排序键、紧凑UTF-8 JSON序列化后的SHA-256；文字/图片许可序列化保持原样：

```json
{"kind":"file","recipient":"12345678901@chatroom","value":"C:\\approved\\报告.pdf","file_sha256":"..."}
```

仅接受本地固定卷、非空、最多100MiB、文件名最多255个UTF-16 code unit的文件；不限制PDF/ZIP/Office等扩展名，不解析或执行文件。100MiB是本实现的预检策略，不宣称是微信服务端限制。路径、祖先目录及文件逐层拒绝重解析点，锁住全部祖先和实际对象后才流式计算SHA-256；实际传入原生对象的是同一卷GUID稳定路径，阻止批准后替换父目录或文件。哈希读缓冲64KiB，不把整个附件装入本DLL内存；微信自身上传时的资源使用未验证。

`FileSendSupported=true` 只表示已实现后端，`FileSendRuntimeVerified=false`、`RuntimeCompatibilityVerified=false`、`DeliveryConfirmed=false` 仍保持。`RetainedPayloadHandles` 为通用路径锁句柄总数；旧 `RetainedImageHandles` 为兼容字段，也计入附件，不是图片数量。

## 固定版本依据

仅接受已有限定的 Weixin.dll 4.1.10.27，SHA-256 `f487e4f56930456a25fb0d7b058c77e2dcd364e268d49bdfff4dc0e3be26ba36`（183094832字节）。未启用自动偏移搜索或兼容其他版本。当前源码未包含上游普通文件实现；补全依据是已有作者发布DLL的磁盘静态反汇编与相同版本腾讯模块的构造/克隆/析构指令，未装载作者DLL执行其逻辑。

| 项目 | RVA / 契约 |
| --- | --- |
| 作者DLL文件接口处理 | RVA0x50CC0；调用原生工厂0x22A92B0，填写附件字段，进入0xDF40和0x1677A30共用链路 |
| 原生附件工厂 | 0x22A92B0，分配0x718字节，控制块0x84F9A78，具体对象在控制块+0x10 |
| 具体对象构造 | 0x6B2D30(object, uuid-string)，vtable0x8279578；对象0x708字节 |
| 具体克隆 | vtable[4]=0x18E41F0 → 0x18E4250，复制构造0x6B4470，相同0x718控制块类型 |
| 对象内字段（相对object） | 接收人0xB0；路径UTF-16字符串0xE0；扩展名UTF-8字符串0x108；文件名UTF-8字符串0x168；字节数0x188；UUID0x6A8 |
| 附件类型/标志 | object+0xD0=0x100000001，object+0xD8=0x600000031（49/6），object+0x100=1 |
| 内部弱引用 | 工厂建立 enable_shared_from_this 弱引用；本实现构造完成、发布前同样设置object+8/+16，strong=1、weak=2；克隆工厂自行绑定各自副本 |

本实现使用原生分配器、实际双参数构造器和共用队列，不手工拼XML链接卡片、不把PDF冒充图片，也不重新加载闭源作者DLL。UUID先准备好；原生构造器使用空UUID初始化，确认目标成员为空后再把本实现的一份字符串所有权移入成员，避免覆盖构造器已有堆对象或留下UUID输入缓冲泄漏。

## 生命周期与失败语义

每条附件复用PR6的对象销毁观察器与Clone观察器。每个对象/克隆持有共享路径锁租约，最后一个已跟踪对象的具体析构返回后才释放锁；不是调用返回或超时后释放。内部弱引用和观察器弱引用分别按其原生析构与回收路径释放。临时参数、源组合状态按原生配对析构回收。

准备阶段只打开/校验文件和版本，不调用本次消息的原生构造器。持久消耗许可成功后才分配、构造、排队；所有构造/排队/析构未知故障沿用隔离保留与禁止后续发送，不重试、不伪报已发送。预检失败不消耗许可；成功进入调用也只有HTTP202/unconfirmed，API不能证明服务端接受或对端送达。

## 离线验证

Windows：`build/build-send-fix.ps1` 运行布局、上下文、预算、真实Prepared预检、API、图片、附件及DLL导出/并发/启动回归。`build/test-native-ownership.ps1 -NativeSample <固定样本>` 运行生产后端的原生指令夹具、10,000次文字/图片/文件混合循环及14个独立故障模式。

夹具在合成进程按需复制固定样本的指令页，替换分配器、UUID、会话提供器和最外层排队函数，明确禁止排队后的真实发送业务体。它验证实际生产准备/构造/克隆/析构与本地路径锁生命周期，**没有验证微信上传、服务端响应、完整消费者路径、账号风险或真实PDF内容是否可打开**。

附件测试覆盖中文文件名、任意二进制内容、摘要错误、路径/收件人/摘要/ID替换、跨类型混淆、未授权/防重放、超限/空文件、UNC/ADS/目录、父目录junction与批准后替换，以及子孙克隆持锁后实际按稳定路径重新打开并比对摘要。macOS对平台无关布局运行ASan/UBSan；这不等于Windows原生调用经过消毒器。

最终断言数、构建摘要和内存采样见 `docs/file-send-results.json`。必须经其他agent审核、用户批准部署后，才考虑一条明确预览并获批准的真实PDF测试；本PR本身不启用任何发送许可。
