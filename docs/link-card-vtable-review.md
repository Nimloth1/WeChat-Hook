# 链接卡片第 8 个虚函数入口修复

## 问题与证据

原生卡片已入队后，微信消费者会通过对象虚表的 `+0x38` 调用第 8 个方法（从 0 起为 slot 7）。旧所有权观察器只为所有媒体复制了 RTTI 加 7 个方法，卡片的这次调用因此越过影子表并将相邻的 `shared_ptr<RequestLease>` 数据当成函数地址。

证据限于 Windows 微信 4.1.10.27，固定 `Weixin.dll` SHA256 为 `f487e4f56930456a25fb0d7b058c77e2dcd364e268d49bdfff4dc0e3be26ba36`。只读静态文件中，卡片对象表 RVA `0x878bda8` 的 slot 7 为 `0x18e5290`；消费者在 `0x5263b44` 执行 `call qword ptr [r8+0x38]`，下一条指令为 `0x5263b48`。已有故障转储的单个栈顶返回地址，换算到微信模块后恰为这个 `0x5263b48`；故障为跳向模块外不可执行堆地址。转储、进程地址、账号和原始消息均未纳入仓库。

转储检查仅增加读取异常线程上下文和一个 8 字节栈顶返回地址，未遍历堆、扫描密钥或附加到运行中的微信。上下文及线程栈结构按 [CONTEXT](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-context) 和 [MINIDUMP_THREAD](https://learn.microsoft.com/en-us/windows/win32/api/minidumpapiset/ns-minidumpapiset-minidump_thread) 解析。

## 修改范围

- 影子表容量改为 RTTI 加 8 个方法；卡片实际复制 8 个，其余图片、文件、视频继续复制 7 个，内存可读范围检查使用对应长度。
- 原对象记录方法数，原生克隆建立子记录时继承同一个数；避免父对象正确而子孙对象重新丢失最后入口。
- 原构造、参数、提交地址、销毁观察器、回收策略、许可及防重放均不变。不扩大其他类型的虚表读取范围。

## Windows 离线验证

使用现有 `tests/native_ownership_fixture.h`，固定文件只映射到独立测试进程；不 `LoadLibrary` 微信、不初始化真实客户端。卡片 slot 7 的具体业务体替换为合成哨兵，只记录调用次数及传入对象；构造、影子表安装、原生克隆及回收仍通过原有生产实现。真实排队消息业务体继续禁止执行。

相同新增测试与旧版 `src/send_ownership.inc` 的对照在第一个 slot 7 调用断言处失败（测试返回 1，SEH 捕获），可重现原先缺失入口。换成修复版后，原对象、子克隆、父及子已释放后的孙克隆均命中哨兵，调用总数恰为 3。

在 PW 的独立目录运行 `build/test-native-ownership.ps1 -NativeSample <固定文件路径>`：正常模式通过 32,177 项断言及 10,000 次混合类型循环；213,221 次原生分配与释放相等，最终句柄差值为 0。另 28 种已有故障模式均通过。正常模式约 4.23 秒，采样工作集约 7.85 MiB；旧/新版编译树的最高采样工作集约 239.49 MiB。每次进程限制 180 秒、1 GiB 工作集及 D 盘 10 GiB 保留空间，测试 PID 专属临时夹具退出后清理。

复现旧版：保留新测试，只将 `src/send_ownership.inc` 换回本分支父提交版本，使用同一脚本编译后单独运行 `send_ownership_tests.exe <固定文件路径> normal`，预期失败在新增 `CallSubmit(...+0x38)` 断言。恢复本分支实现后应运行完整脚本通过。不要用旧版执行全故障集并将预期失败误报为修复失败。

候选发送 DLL 另行编译成功，SHA256 `f6aa6a8f25fcde160475ba03174a710779af514566c86049628cb75ffeb12927`，约 18.17 秒、采样编译树约 236.45 MiB。没有重跑与本次改动无关的完整 DLL 回归集；完整本次结果见 [link-card-vtable-results.json](link-card-vtable-results.json)。

## 上线边界

本次完成的是明确越界入口的修复及离线验证，尚未证明真实卡片上传、消费者后续参数行为、实际送达或账号安全。修复版未部署、未在真实微信中加载、未创建许可或试发；不能将合成哨兵称为完整原生业务体测试。当前生产保持“发送人、标题、URL”的普通文字转发，先独立审核此补丁，再在具体部署和测试授权内验证原生卡片。既有结果未知卡片不得重试。
