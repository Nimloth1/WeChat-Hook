# 连续发送资源保留与回收研究

本文件保留前两个阶段的历史研究，不能用其中旧候选或“尚未接入”的阶段状态判断当前代码。后续已把配对回收接入生产后端；当前实现、离线验证及真实异步链的未验证边界见 [回收实现审查说明](send-reclamation-review.md)。本文的累计保护实验本身仍不能证明长期运行。

## 已确认问题及保护

独立审核在 `7d71c31` 用实际 Arena/BuildFrame/ExecuteFrame 和 NativePrepared 保留路径，合成 8 条文字、4 条图片：累计分配 179,200 字节、116 次分配、0 次释放；4 张图片保留 12 个合成句柄。每份新许可都新建 Arena，原来的单帧 128 KiB 限制无法约束累计量。每次进入原生路径都会发生，不需要并发或异常，是静默增长。

现为整个 DLL 实例的生产 backend 共用预算：本模块显式分配的参数最多 16 MiB、图片文件和所有父目录句柄共计最多 256 个。额度同时包含准备中的预留量与已经永久保留的量。NativePrepared 在完整构造参数后、Controller 调用 ConsumeApproval 前预留；失败返回 HTTP 503 / `native_retention_budget_exceeded` / `native_entered=false`，许可和持久消耗标记不变。

未进入私有调用的撤销、消耗失败、构造失败会通过 RAII 释放本次参数和句柄，并退还预留。进入私有调用前明确保留 Arena、图片句柄及预算；即使构造器/后续调用报告失败，也不自动释放或退还。更换许可、controller 或 backend 不会重置生产预算。没有重置额度接口、定时释放、自动重启或自动重试。

额度不是微信 RSS、整进程堆或原生函数内部创建对象的上限。构造期间仍允许单帧最多 128 KiB 的临时参数；额度失败时释放本帧，这些瞬时准备分配不属于永久保留。达到上限后停止接受新的原生调用；本改动不要求每条重开，也不承诺永远不重开。`NativeResourceReclamationVerified=false` 明确表示未打通回收；状态同时报告参数/句柄计数和各自上限。HTTP 状态的授权快照与资源快照分别读取，不作为原子事务或送达证明。

## 实际静态证据

仅从磁盘读取 4.1.10.27 的 Weixin.dll，SHA256 `f487e4f56930456a25fb0d7b058c77e2dcd364e268d49bdfff4dc0e3be26ba36`；不打开目标进程、不加载模块、不执行所提取机器码。小片段只用 LLVM 反汇编，原始片段与日志保存在本地任务输出，不将私有二进制放进仓库。

| 位置（RVA） | 实际观察 | 能否据此释放 |
| --- | --- | --- |
| `0x1677A30–0x1677D39` | 发送入口从第一个参数的范围复制 16 字节元素；`0x1677B28`、`0x1677C38` 对复制元素的第二指针 `+8` 执行原子增加；随后把复制结果交给其他对象/函数 | 原始消息引用参与复制；函数返回不能证明消费者结束 |
| `0x1677CCC` 后及 `0x1677CFC` 后 | 局部对象路径原子减少 `+8` 字段，零时调用虚表函数，再减少 `+12` 字段并有第二个虚表调用 | 与引用计数销毁形态一致；不是针对本次 HTTP 请求的完成通知 |
| `0xDF40–0xE161` | 参数构造在 `0xDF6F` 调用分配入口 `0x680D0FC`；`0xDF75` 写入 `0x100000001`；结果通过输出对象保存；并包含虚表调用、移动/清空输入字段 | 存在微信自己创建的对象；只释放本模块 Arena 不代表释放全部资源 |
| `0x5A8A0–0x5A9BD` | 被发送函数调用的复制路径既有 `+8` 原子增加，也有复制/虚表克隆及 `+12` 原子增加 | 强/弱引用风格的生命周期不等于一个“调用完毕即可 free”的契约 |
| `0x6B2C30–0x6B2CF3`、`0x6B2D30–0x6B302D` | 文本构造器还调用其他构造器、初始化多个成员并设置对象虚表；不是仅复制用户正文 | 必须区分本模块分配、微信内部分配和成员销毁，不能跳过全部析构或混用分配器 |

上述范围有 PE runtime function 边界支持；额外 `0xA800`、`0xA830` 是各 128 字节的有界窗口，缺少 runtime function 记录，不把整窗口当成单一函数。`0x1678000` 的清理代码已记录，但尚未证明它适用于本代码每一种参数对象，**未增加任何对它的调用**。

当前 BuildFrame 从上游沿用消息头 `+8` 的 `0x200000005` / `0x200000006`；这些位模式与上述原子计数布局相邻，但不是经验证的一份调用方所有权。不能擅自改成 1，不能遍历堆或猜测虚表后调用析构。生产分配器是 `HeapAlloc(GetProcessHeap())`，原生代码另有自己的分配/释放入口；尚未证明两者可互换。

微软说明 shared ownership 在最后一份所有权结束时销毁资源，控制块还可能等待弱引用消失；这仅用于解释静态代码形态，不能替代微信私有 ABI 的证据。[shared_ptr 官方文档](https://learn.microsoft.com/en-us/cpp/standard-library/shared-ptr-class)

上游 `src/wx_send.cpp` 的 SendText/SendImg 路线只构造参数并调用发送函数，没有可直接复用的回收/完成接口。[上游代码](https://github.com/aixed/WeChat-Hook/blob/main/src/wx_send.cpp)

## 安全回收尚缺的契约

1. 正文/图片消息、参数输出、克隆节点及临时缓冲各自属于谁，哪些被复制、移动或借用。
2. 每类对象的匹配分配器、正确析构和异常中途的撤销路径；包括文本构造器内部创建的成员。
3. 能绑定到某次请求的最终释放事件，或可验证的所有权转交；不能只读一个计数后与其他线程竞争释放。
4. 图片完成读取原路径的条件；正文可回收并不自动证明文件和父目录锁也可以释放。

“返回后释放”“等几分钟释放”“只看当前引用计数”均没有足够依据。当前只完成未进入原生路径时的确定性回收及入场后的累计保护；**已进入原生路径的安全回收未完成，长期连续运行目标未完成**。本次没有因此扩大到真实微信探针、热替换、重新登录、真实发送或 VW11 操作。

### 新定位的真实所有权链

在相同摘要的磁盘文件中继续追踪：

| RVA | 观察到的契约与限制 |
| --- | --- |
| `0x6B40F0` | 文字复制工厂分配 `0x758` 字节并先写入 `0x100000001`，随后复制消息并登记自身弱引用。因此初始 `1/1` 字面值并不代表所有后续时刻都保持 `1/1`。 |
| `0xA7F0` | 取控制块 `+16` 的消息对象，通过其虚表调用不释放对象存储的析构。之前只有 `0xA800` 窗口，未见这条完整入口。 |
| `0xA800 → 0xA7D0 → 0x680D138` | 最后弱引用路径通过控制块虚表调用带删除标志的释放，最终进入微信配对的释放入口。 |
| `0x6B3FD0 → 0x6B4000` | 文字析构先处理正文/at 字符串，再处理基类；大字符串达到 4096 字节后从缓冲前 8 字节取得原始分配指针。不能混用当前 `HeapAlloc` 字符串后直接调用它。 |
| `0x17781D0 → 0x1778200` | 图片对象同样有具体成员析构，并继续调用基类析构；不是释放一块平坦缓冲即可。 |
| `0x1678180`、`0x1678660` | 发送任务复制持有的消息引用及参数对象；任务销毁调用其组合状态的析构。 |
| `0x1678000` | **组合状态析构**：向量后面还有参数与三个类型擦除回调，读取范围到 `+0xF8`。不能将它当成可作用于任意 24 字节向量的通用析构。 |
| `0x1778170` | 图片虚函数可生成另一个控制块、消息对象和独立复制的文件路径；原对象的最终销毁不能代表所有相关路径消费者结束。 |
| `0x1678320 → 0x16BED80 / 0x16BD660` | 排队后的真实工作还有多层消息处理和新的引用传递；本轮夹具没有执行这部分业务工作。 |
| `0x1678710 → 0x529F0 / 0x5AF90` | 涉及结果处理、共享标志、全局同步和回调执行。特别是 `0x5AF90` 会改变状态并调用回调，**不是只读完成查询或内存析构**，不能拿来清理资源。 |

由此可以排除三种捷径：只减少上游人工计数、在 `Run()` 返回后直接 `free` 全部 Arena、在原图片消息析构时就关闭文件锁。前两者还混淆当前分配器/字符串对齐和中途失败状态；最后一种已存在真实图片克隆的离线反例。

### 可复跑的真实指令夹具

新增 `tests/native_ownership_probe.py`。要求本地已有指定 SHA256 的 Weixin.dll 和 `unicorn==2.1.4`；不下载、加载或初始化微信 DLL，不开目标进程，不读数据库、不连接 HTTP。固定合成收件人和合成内存地址，无真实账号、群、正文或许可。输入版本或摘要不匹配直接拒绝。

```powershell
python -B tests/native_ownership_probe.py --native D:\offline\Weixin.dll --cycles 1000
```

只在 CPU 模拟器中运行实际构造、参数复制、引用增加/减少及析构指令。配对分配/释放、memcpy、固定 UUID、会话提供器和最外层排队入口由夹具替代；回调捕获为空。夹具在队列边界截留任务，实际执行任务复制和销毁，**不执行真实消息工作体**，不模拟或验证真实文件 I/O、异常展开或账号状态。

验证包含：原人工计数与配对计数对照、正文 SSO/4096 字节边界/32768 字节、较大 UTF-16 路径、任务复制后先销毁一份仍保留消息、最后任务销毁后的参数回收，以及图片深复制后原对象先销毁而克隆路径仍存在。所有模拟堆访问检查分配范围，非法访问/重复释放报错；模拟堆 16 MiB，映射原文件页面最多 32 MiB，每次调用 10 万指令/2 秒，完整循环 150 秒，外部另监测 1 GiB 工作集采样停止线和 180 秒超时。它们不是生产进程的资源保护。

原始摘要、对照计数和最终脚本复核结果一并保存在 [可审查结果](native-ownership-probe-results.json)。夹具构造原生布局的合成对象，**不是运行生产 `NativePrepared` 或 Arena**。

### 生产接入仍缺什么

已经验证的可行方向是遵守原生引用所有权，并配对原生分配器、成员析构及调用方引用释放；不是定时 `free` 或定期重启。不过仍有两个未闭合条件：真实消息工作体对对象/回调的转交及私有构造器中途失败时的可清理边界；以及图片所有克隆和按路径延迟读图的结束条件。单个引用归零、最外层队列销毁、结果回调或一句“发送完成”不能自动代替最后一个条件。

接入还必须保持许可顺序：当前 Prepare 不执行私有函数。将 `HeapAlloc` 直接换成私有原生分配器会把私有调用提前到许可消耗之前，同样不可接受。真正接入需在许可校验/持久消耗后建立拥有正确析构契约的对象，成功时转交引用；无法证明的部分仍保守保留并响亮报告。不能用本轮夹具作为这些接入条件已经通过的证明。

本轮没有修改生产参数布局/引用计数、虚表、回调、分配器、发送/重试逻辑、微信文件或许可。未实施定时回收、热卸载或新的真实探针。只通过 SFTP 读出一份磁盘 DLL 静态样本，在 PW 隔离目录执行模拟器；没有运行微信模块、操作登录、发送消息或访问 VW11。

### 本轮实际结果

PW Python 3.8.5 / Unicorn 2.1.4：完整 1000 轮、2024 项检查通过，17,500 次模拟参数分配，每轮销毁任务副本后均回到零分配；模拟参数堆单轮峰值 9,583 字节。文字原计数对照最终仍有 4 个分配、7,007 字节，图片原计数仍有 4 个分配、2,112 字节。配对计数和配对析构的两个对照均为零残留。图片深复制反例确认原对象已销毁而独立路径副本仍存活。

这 1000 轮只在队列边界复制、读取引用和销毁任务，不执行真实消息工作体，不能称为 1000 次真实发送、送达、真实微信无泄漏或图片句柄回收通过。完整过程 99.8 秒，采样工作集峰值 350,445,568 字节。Mac 模拟器在自身初始化时触发 SIGILL，尚未执行本样本指令；因此只采用 PW 的通过结果。

最终脚本将收件人字面量改为同长度合成 ID 后另跑 100 轮、224 项检查通过，11.5 秒，采样峰值 75,059,200 字节。生产 C++、许可及部署文件均未改；未重编或部署 DLL。已有 `c33c136c…` 候选仍只对应累计保护，不能据此宣称生产安全回收已实现。
